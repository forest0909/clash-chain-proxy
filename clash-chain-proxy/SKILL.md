# Clash 链式代理

为选定订阅配置链式代理：选择组 `MyIP`，SOCKS5 节点 `MyAI`。链路为设备 → 订阅上游节点 → SOCKS5 → 目标服务。默认附带 Claude 分流规则，见 `assets/claude-rules.yaml`；客户可以追加域名、IP 或进程规则，让其他指定流量使用同一代理链。已有分流规则保留。

## 开始前

- 运行环境：Python 3、PyYAML。缺少依赖时使用该 Python 环境安装 `pyyaml`，不要更改系统 Python。
- 下文脚本路径相对本 Skill 根目录，执行时使用绝对路径。用户配置保存在用户自己的目录，不能把真实凭证写进 Skill 包或命令行参数。
- 脚本默认只读预览；客户请求配置并选定订阅后，即授权为这些订阅生成链式代理配置，直接使用 `--prepare --apply`，不再单独询问是否写入。脚本会自动备份。还原、接管用途不明的同名对象或扩大订阅范围仍需单独确认。
- 不更改 Clash 的代理模式、DNS、TUN、订阅链接或系统代理。既有全局/订阅脚本和 provider 也可能影响最终行为，不能只凭生成成功宣称已生效。

## 首次配置：选择订阅

执行：

```sh
python3 scripts/configure.py --list
```

自动查找 macOS/Windows/Linux 常用目录；找不到或不唯一时，请客户提供包含 `profiles.yaml` 的配置目录，用 `--dir "目录"`。不要猜测、下载订阅或输出订阅 URL。

客户只说“帮我配置链式代理”等、尚未指定订阅时，先运行上述只读列表命令，将全部订阅按返回顺序整理为从 1 开始的编号列表，名称使用实际读取结果，并标记当前订阅。不要只展示当前订阅或默认替客户选中它，也不要用截图里的历史名单代替实际读取。

列表后询问：“需要配置哪些订阅？回复编号即可，可多选（例如 `1 3`）。选定后会直接写入链式代理配置并自动备份，再补连接信息。目前还没有修改配置。”此时等待客户选择，暂不询问 SOCKS5 连接信息。

将客户回复的编号对应到刚才展示列表中的 UID；支持空格或逗号分隔的多个编号，重复选择只处理一次。编号不存在时请客户重新选择。编号只用于对话选择，不直接传给脚本。选定后逐个执行下列命令，直接完成待填配置，不停下来询问填写方式或再次确认写入：

```sh
python3 scripts/configure.py --dir "配置目录" --subscription "UID" --prepare --apply
```

多选时处理全部选定订阅，再汇总成功项、失败项及缺失信息。遇到用途不明的同名对象时保留脚本的接管保护，不自动添加 `--adopt-existing`。

客户已明确指定订阅名称、UID 或“当前订阅”时，可直接匹配列表中的对应 UID；有歧义时再询问，不必重复要求编号选择。

若缺少节点/代理组/规则/脚本扩展关联，引导客户在该订阅右键菜单打开对应编辑器并保存，再重新读取。脚本不直接改写 `profiles.yaml`。

## 连接信息：由客户选择方式

先完成选定订阅的配置写入，再报告“链式代理配置已写入，连接信息尚待补齐”，列出需要补充的服务器地址、端口、用户名和密码（无认证可不填后两项），最后询问“你自己在 Clash 中填，还是由我代填？”不强制索取密码。已有连接信息由脚本在本地沿用，不读取或展示密码，也不将已齐全的信息说成缺失；地址端口齐全时只说明尚未验证连通性，不重复索取。未成功写入时如实报告原因，不声称已配置完成。

### 客户愿意提供

需要 `server`（服务器地址）、`port`（端口）、`username`（用户名）、`password`（密码）。无认证代理的用户名和密码可留空，不凭空补值。

将 `assets/user-config.example.yaml` 复制到客户自己的目录并填入，文件权限尽可能限制为当前用户读写。通过文件工具安全写入，避免将凭证拼进 shell 命令、输出、截图或回复。只报告“已填写”，不回显密码。没有明确授权时不要读取现存凭证；脚本可以在本地沿用而无需把它展示给模型。

### 客户自行填写

待填配置已在选定订阅后写入，直接引导客户填写，无需再次生成或确认。尚未填写时不要激活订阅。

按客户提供的界面路径引导：

1. 左侧“订阅”，找到当前选定的订阅。
2. 右键“编辑节点”，点击弹窗右上角“高级”。
3. 找到 `prepend` 中名称为 `MyAI` 的节点，填写四项。

| 字段 | 客户填写内容 |
|---|---|
| `server` | 固定 IP 服务商提供的 SOCKS5 服务器 IP 或域名 |
| `port` | SOCKS5 端口，整数，不加引号 |
| `username` | 服务商提供的用户名，无认证则留空 |
| `password` | 服务商提供的密码，无认证则留空 |

名称 `MyAI`、协议 `socks5`、`dialer-proxy` 保持生成值，不要求客户判断上游组。字符串使用 YAML 引号，包含单引号时采用正确 YAML 转义；不要要求客户回传包含密码的截图。截图旧名称 MySOCKS 对应这里的 MyAI。

该页面展示已填入的信息，不会自动获取固定 IP。首次没有代理信息时请客户向自己的服务商获取。本 Skill 不提供或购买固定 IP。

客户保存并回复“已填写”后，再运行不带 `--prepare` 的预览，检测地址与端口是否齐全；不读取或展示其密码。后续用户配置文件的空字段代表沿用已有值，不覆盖成空。客户手填后让外部配置文件对应凭证保持空，避免旧值再次覆盖。

## 追加规则：先筛选已有链式代理订阅

客户说“加个规则”“这个网站也放进去”等时，先执行以下只读扫描；不要从当前项目有没有配置文件推断本机没有 Clash 配置，也不要先让客户解释软件、提供规则文件或重新选择直连/代理。首次配置才使用前文的全量订阅列表。

```sh
python3 scripts/configure.py --list-configured
```

自动查找配置目录；只有查找失败或不唯一时才询问目录，再用 `--dir "配置目录" --list-configured`。扫描所有本地和远程订阅的关联扩展，检查唯一的 SOCKS5 节点 `MyAI`（含上游 `dialer-proxy`）、select 组 `MyIP` 及其对 `MyAI` 的引用；不输出地址、端口、用户名、密码或订阅链接。它只证明存在链式代理配置，不代表连接可用。

将返回的 `subscriptions` 按原顺序编号并列出实际名称，标记当前订阅。只列符合条件的候选，不混入其他订阅。例如共 10 个订阅、只有 2 个配置了链式代理，就只展示这 2 个。询问：“要把这个网站的规则加到哪个订阅？回复编号即可，可多选（例如 `1 2`）。目前还没有修改配置。”即使只有一个候选也先列出并等待选择。若客户已明确指定名称、UID 或“当前订阅”，先核对其属于候选且唯一，再直接处理。

将编号映射到本次候选的 UID，支持空格或逗号分隔，重复编号去重；无效编号要求重新选择，不能当作 UID。选定后先预览，再加 `--apply` 写入并自动备份，无需再次确认。保留接管保护：候选 `managed: false` 表示没有本工具的管理记录，展示时标记“需确认接管”；客户只选编号不等于确认接管，明确确认用途后才加 `--adopt-existing`。

没有候选时说明“未检测到符合条件的链式代理订阅”，询问是否进入首次配置流程，不自动给其他订阅新建链式代理。返回的 `skipped` 是缺文件、冲突或读取失败项，单独概述为“未能完整检测”，不能说这些订阅没有配置；单个异常不影响其他订阅的候选展示。

从用户提供的网址提取主机名，去掉协议、端口、路径、查询参数和片段；默认添加精确域名规则。例如 `https://cleanip.io/who-am-i` 对应 `DOMAIN,cleanip.io,MyIP`。只有客户要求包括子域名时才使用 DOMAIN-SUFFIX，不把整条 URL 当作域名，不为提取域名而访问网站。

## 应用与追加规则

用户配置包含 `connection` 和 `custom_rules`。修改配置时保留已有自定义项。客户可以手工修改，也可以要求你添加，例如：

```yaml
custom_rules:
  - DOMAIN-SUFFIX,example.com,MyIP
  - DOMAIN,api.example.org,MyIP
  - PROCESS-NAME,ExampleApp,MyIP
  - IP-CIDR,192.0.2.0/24,MyIP,no-resolve
```

域名后缀匹配包括根域名和子域名；精确匹配用 DOMAIN。进程规则是否可用取决于客户实际平台、进程名称和内核设置，不承诺仅靠进程规则覆盖全部请求。

支持 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6、PROCESS-NAME，出口固定为 MyIP。追加规则放在内置规则前，随后保留已有 prepend 规则，去除完全相同的重复项；原 append/delete 保留。此版支持追加，不提供规则删除命令，删除要明确识别配置文件和 Clash 扩展中的对应项后单独处理。

预览命令：

```sh
python3 scripts/configure.py --dir "配置目录" --subscription "UID" --config "用户配置文件"
```

追加规则时只在用户配置中追加 `custom_rules`，不填写或读取现存凭证；已有连接信息在本地沿用。候选节点尚未填齐时，预览和应用均加 `--prepare`，允许先加规则，但告知补齐前暂勿激活。

客户手填连接信息且没有额外配置文件时，可省略 `--config`，沿用现存节点。初次待填加 `--prepare`。预览仅输出对象、数量和填写状态，不输出连接信息。

预览后说明：会更新 MyAI/MyIP 两个同名对象、补充规则，并在原订阅脚本之后追加防循环逻辑；其他扩展数据保留，YAML 注释和排版会重新生成。第一次遇到已有同名对象会停止，确认它们就是客户要接管的对象后才使用 `--adopt-existing`；不能把无关同名节点当作本 Skill 节点。

首次配置按“选择订阅”直接使用 `--prepare --apply`；后续客户明确要求代填或追加规则时，先运行预览检查，再使用相同参数加 `--apply`，无需重复索取已有授权。每次真正改动都会创建唯一备份，不覆盖旧备份。禁止直接运行项目旧版个人脚本，它会覆盖整个扩展文件。

防循环逻辑保留原 main 的处理，在其结果中从非 MyIP 组的显式 proxies 列表排除 MyAI 和 MyIP，避免订阅上游组反选这条链。它不证明所有 provider 动态引用或全局脚本都无环；存在这类配置时，检查最终生成的配置，失败则停止并检查日志，不能反复盲目重写。

## 激活、检查和还原

1. 连接信息已填写后，客户在 Clash 中重新点击使用/激活该订阅。
2. 在代理页选择 `MyIP → MyAI`，并确认上游代理组选择了可连接的订阅节点。
3. 让客户在使用 Clash 代理的本机浏览器打开 https://ip.net.coffee/claude/ 做测试，不再引导客户访问 Claude 官网或登录 Claude 测试。默认规则包含 `DOMAIN,ip.net.coffee,MyIP`，让检测页面使用同一代理链；已有配置需要重新运行配置脚本补齐该规则并重新激活订阅。
4. 查看检测页面的 Claude AI 出口 IP、可用性检测结果，并在 Clash 连接记录中确认检测请求实际经过 `MyIP → MyAI`。页面可能请求其他检测域名，若其请求没有命中该链路，先核对实际域名和规则，不凭页面成功打开或某个 IP 值宣称验证通过。远程抓取页面不能代表客户本机的代理出口。地址端口齐全、脚本执行成功均不等于连通性或固定出口验证通过；第三方检测结果也不保证 Claude 账号可用。

还原时先预览备份编号，确认后才写入：

```sh
python3 scripts/configure.py --dir "配置目录" --restore "备份编号"
python3 scripts/configure.py --dir "配置目录" --restore "备份编号" --apply
```

备份位于配置目录 `.claude-chain-backups/编号`，可能包含凭证，不打包或展示。文件如在此次写入后发生变化，自动还原会停止，避免覆盖客户后续手填内容；此时先人工比较并说明影响，不绕过保护。需要退回多次变更时从最新备份逐次还原。
